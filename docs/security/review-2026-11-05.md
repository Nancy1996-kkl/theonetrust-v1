# Security and privacy review — 2026-11-05 (#38)

Scope: whole repository at `feat/38-security-review` (on top of #37). Method: read the code paths
against `docs/threat-model.md`, PROJECT_SPEC §12 and OWASP ASVS 5.0 L1–L2; run the automated
scans; run the full e2e suite under the new Content-Security-Policy.

**Result: no unresolved critical or high finding.** Two high findings were found and fixed in

## Checked and found in order

- **Payment trace** (intent → order → checkout → callback verify → webhook → status → receipt →
  email): amounts are server-side integer paise; checkout and webhook signatures are verified on
  the server with constant-time comparison; amount, currency and order are re-checked against
  Razorpay and a mismatch goes to manual review; webhook events are unique per provider event ID
  and payment ID; status only moves forward; receipts are issued once per payment; monthly
  charges reuse the same reconcile path. (Traced in the code for this review; the
  `payment-security-reviewer` agent definition is unchanged.)
- **Session cookie**: `__Host-` prefix in production, HttpOnly, Secure, SameSite=Strict, Path=/.
- **CSRF**: token bound to the session + Origin allowlist on POST/PUT/PATCH/DELETE.
- **CORS**: explicit origin allowlist, credentials only for those origins.
- **Rate limits**: global per IP + stricter per-route limits on sign-in, donations, verify,
  status, help requests, receipts and manage links.
- **Uploads**: real type from bytes, declared type and extension must agree, size limit,
  private storage outside the web root under generated keys, served only when published, `nosniff`.
- **Secrets**: none committed (`check:no-live-keys`), none in the built bundle (`check:bundle`).
- **Personal data**: never in URLs or logs (query strings dropped from request logs); PAN and
  address encrypted with AES-256-GCM, masked in the dashboard, decrypted only in the audited
  Form 113 export.
- **Admin access control**: enforced in the API on every request, including unknown paths.
